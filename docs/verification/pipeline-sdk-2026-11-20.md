# ATK SDK 독립 설치 검증

2026-11-20 Windows, Node.js 24.16.0에서 `agentic-task-kit@0.2.0-sdk.1`의 all-in-one 패키지를 검증했다. 배포 파일은 `out/pipeline-sdk/agentic-task-kit-0.2.0-sdk.1.tgz`이며 SHA-256은 `36399e3ea09d4a9ea3e25550c6626b3f82e6b771ad74447c71ebf360a718b096`이다.

### 외부 에이전트가 구성한 실행

새 프로젝트에서 `workflow_describe`로 읽은 작업 카탈로그, 입력·출력 계약, 사용자 목표와 문장만 독립 Astra 에이전트에 제공했다. 목표는 양끝 공백을 정리한 문장의 단어 수를 짧은 보고서로 출력하는 것이었다. 입력은 `"  red blue gold green  "`였다. 에이전트가 작성한 아래 계획을 패키지의 `submitted-report` 프로필에 제출했다.

| 체크포인트 | 단계 ID | 선택한 작업 | 데이터 연결 |
| --- | --- | --- | --- |
| 1 | `trim` | `normalize` | 요청의 `text` |
| 2 | `count` | `count_words` | `trim.text` → 별도 MCP 프로세스 호출 |
| 3 | `report` | `format` | `count.count` → 최종 보고서 |

프로필에 `maxSteps: 1`을 지정해 단계마다 커밋했다. 첫 번째와 두 번째 체크포인트에서 클라이언트를 닫고 새 stdio 연결에서 같은 실행 `8f0f6fe8-66ba-4d87-a47c-8eed593a5c88`을 재개했다. 세 번째 체크포인트에서 완료됐으며 결과는 `{"report":"Words: 4"}`였다. `workflow_results`에서 내려받은 `pipeline-plan`의 단계·인수 연결은 제출한 계획과 일치했다. 해당 산출물의 SHA-256은 `ec6dfe1e780b5782818ca66152fdb94b220be114b0f0a6d0b801f02a59129904`이다.

### 자동 검증

- 전체 테스트 26개 파일, 242개 통과. 타입 검사, 108개 소스 모듈의 런타임 순환 검사, 일반·배포 패키지 각각의 108개 모듈 import 검사 통과.
- `npm run test:sdk-package`는 새 폴더에 실제 tgz 설치 → 프로젝트 생성 → 로컬 실행 → stdio 발견 → 요청 거부와 정상 시작 → 계획 수정 → 실행 중단 → 새 연결에서 재개 → 검증된 결과 다운로드를 확인한다. 임베디드 서버의 실행 시작과 외부 에이전트 제출 프로필도 확인한다.
- 서버 내부 모델 경로는 로컬 HTTP 모의 제공자가 첫 번째 잘못된 계획을 반환하고 두 번째에 수정하도록 구성했다. 재개할 때 모델 설정 파일을 사용할 수 없어도 결과를 회수했다. 실제 모델이 선택한 계획은 위 외부 Astra 경로에서 별도로 실행했다.
- 기존 consumer 예제와 sample-project 타입 검사가 통과했다. 공개 레지스트리 배포 및 현장 설치 전의 로컬 검증 결과다.
